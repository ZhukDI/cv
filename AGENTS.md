# AGENTS.md

Astro 7 static CV site (single page, zero client-side JS). Content, layout, and print styling are the main surfaces of change.

## Commands

- `npm run dev` — dev server at `localhost:4321`
- `npm run build` — production build to `./dist/`
- `npm run preview` — serve the built `dist/`
- There are **no lint, test, or typecheck scripts** and TypeScript isn't installed locally (`astro check`/`tsc` will not run). `npm run build` is the only verification step; it type-checks the frontmatter of `.astro` files.

## Architecture

- All CV content lives in `src/data/cv.ts` (`CV_DATA`). Edit content there, not in components — pages/components (`src/pages/index.astro`, `src/components/*`) only render it.
- Tailwind CSS **v4** via `@tailwindcss/vite`: CSS-first config, no `tailwind.config.js`. Theme tokens and dark-mode variables live in `src/styles/global.css` (`@theme` block, HSL CSS variables like `--primary` → `bg-primary`).
- `site: 'https://cv.dzhuk.com'` in `astro.config.mjs` drives canonical URLs, `@astrojs/sitemap`, and `robots.txt` (generated by `src/pages/robots.txt.ts`, which links `sitemap-index.xml`). Keep it in sync with the real domain.
- Design constraint: no client-side JavaScript; the layout is print-optimized (see `print:` variants and `.print-force-new-page` in `global.css`). Don't add scripts or break print rendering.

## Docker / Nginx

- Multi-stage `Dockerfile`: `node:24-alpine` builds the site, nginx (alpine) serves `dist/`.
- `docker-compose.yml` runs the **published image** `zhukdi/dzhuk-cv:latest` (port 8080→80) — it does not build local changes. To test locally, build manually: `docker build -t zhukdi/dzhuk-cv:latest .`
- `nginx/nginx.conf` includes `nginx/security-headers.conf` inside every `location` on purpose: nginx `add_header` directives in a location suppress all inherited headers. New locations must include it too.
- `error_page 404 /404.html` maps to `src/pages/404.astro` — don't rename or remove that page, or nginx 404s break.

## Notes

- Node 22+ required (README); Dockerfile uses Node 24.
- Dependency updates come via Renovate (semantic-commit PR titles, grouped non-major updates) — don't hand-edit `package-lock.json`.
